## 3. 功能目标与用户画像

`observed` 现状：本系统的通联记录（`QsoRecord`，呼号、日期、时间、频率、模式等）只能由人工录入、Excel/ADIF 导入或实体卡申请书反向生成；用户在 LoTW（ARRL Logbook of the World）、QRZ Logbook、Club Log、eQSL 上已有的通联记录无法进入本系统。

目标：

1. 在「配置」中为本台呼号（`StationProfile.spec.myCallSign`）配置一个或多个外部日志源与凭据。
2. 一键（或按周期）从外部源拉取该呼号的通联记录，服务端解析为标准记录后写入 `QsoRecord`。
3. 重复拉取不得产生重复记录；已存在记录默认不覆盖人工编辑内容。
4. 每次同步留下可追溯的作业记录（who/when/拉了多少/新增多少/跳过多少/失败原因），并写审计日志。

用户可见结果：外部日志里已有的 QSO，在本系统「通联记录」页可见，可继续走制卡、发信、收卡流程；`QsoRecord.status.source` 标明来源，便于区分人工录入与外部同步。

## 4. 数据源能力矩阵

> 本节是设计的前提，核验日期 2026-10-31。若某源无可用接口，则该源只能退化为「用户手工下载 ADIF 后走现有导入」，不得伪造自动化路径。

| 数据源 | 是否有官方 API | 认证方式 | 拉取形态 | 增量能力 | 结论 |
| --- | --- | --- | --- | --- | --- |
| ARRL LoTW | **无** | 呼号 + 密码（HTTP 查询串） | 未公开的 ADIF 下载地址 | 有（`qso_qsorxsince`） | 可做，但属非官方接口，脆弱 |
| QRZ Logbook | **有** | API Access Key | `POST https://logbook.qrz.com/api`，`ACTION=FETCH` 返回 `ADIF=` | 有（`AFTERLOGID`、`MODSINCE`） | 最规范，但 FETCH 需订阅 |
| Club Log | 文档化的只有上传 | email + 密码/应用密码 | 上传 `putlogs.php`/`realtime.php` 有文档；**下载未见官方文档** | 未核实 | 未核实，不建议首期做 |
| eQSL.cc | 有（半文档化） | 呼号 + 密码（HTTP 查询串） | `DownloadInBox.cfm` → HTML 页面里两个 ADIF 链接（两步） | 有（`RcvdSince`） | 语义不符，见 4.4 |

### 4.1 ARRL LoTW（证据：`documented` 缺失 + 社区 `observed`）

1. **ARRL 未提供任何程序化接口**。ARRL-LoTW 邮件列表原话：「There is no defined programmatic interface」（[groups.arrl.org/g/ARRL-LoTW/message/151](https://groups.arrl.org/g/ARRL-LoTW/message/151)），另一处说明 ARRL 只公开了非最终的源码、没有 API 文档（[ARRL-LoTW 列表](https://groups.arrl.org/g/ARRL-LoTW/messages?page=2106&before=1065666232000000000)）。
2. 实际可用的做法是 LoTW「Your QSOs」页面背后的 ADIF 下载地址，社区通用形态（[哈罗 CQ 社区帖](https://awards.crac.org.cn/forum/m/index.php?a=read&tid=378007)、[ARRL-LoTW message 2878](https://groups.arrl.org/g/ARRL-LoTW/message/2878)）：

   ```text
   https://lotw.arrl.org/lotwuser/lotwreport.adi
     ?login=<呼号>
     &password=<密码>
     &qso_query=1
     &qso_qsl=no           # no=全部 QSO；yes=只含已确认
     &qso_qsorxsince=YYYY-MM-DD
     &qso_withown=yes
   ```

3. 风险与设计约束：

   - **凭据在 URL 查询串里** → 命中第 11.2 节脱敏红线，必须禁止任何形式的 URL 落日志。
   - 非官方接口，ARRL 改版即失效 → 必须有「解析失败」的稳定错误码（`QSL-422-LS-0003`）与友好提示，且失败不影响系统其余功能。
   - 属爬取式访问，必须严格限速（默认最短间隔 60 分钟、单次全量、每日最多 1 次全量），并在页面明示「非官方接口，频率过高可能被 ARRL 限制」。
   - ARRL 商标条款限制第三方产品在名称中使用 "LoTW"/"Logbook of the World"（[arrl-license 原文](http://rsync.netbsd.org/pub/pkgsrc/current/pkgsrc/licenses/arrl-license)）→ **功能命名统一用「外部日志同步」，界面文案写「ARRL Logbook of the World（LoTW）数据源」这类描述性表述，不把 LoTW 放进产品名或菜单名。**

### 4.2 QRZ Logbook（`documented`，[官方 API 文档](https://www.qrz.com/docs/logbook/QRZLogbookAPI.html)）

1. 端点 `POST https://logbook.qrz.com/api`，`name=value` 表单，必须带 `KEY`（按 logbook 发放的不透明 Access Key）与 `ACTION`。
2. 拉取：`ACTION=FETCH`，`OPTION` 为逗号分隔的 `name:value`，本设计用到：

   - `AFTERLOGID:<n>` —— 增量游标（只取 `app_qrzlog_logid >= n`）
   - `MAX:<n>` —— 分页，官方建议 250 一条一批
   - `STATUS:ALL|CONFIRMED` —— 是否只要已确认
   - `TYPE:ADIF` —— 返回 ADIF

3. 响应为 `key=value&` 串，ADIF 内容在 `ADIF=` 参数里（需 URL 解码）；`RESULT=OK|FAIL|AUTH`、`REASON` 为失败原因。
4. 官方要求：**必须提供可识别的 User-Agent**（含呼号与脚本名，≤128 字符），否则可能被限流。
5. `FETCH` 官方标注 **Note: subscription required** —— 用户如果不是 QRZ 付费订阅用户，该源不可用。这必须在页面上明确提示，不能当成普通失败。
6. 设计影响：`LogSyncProfile.lastCursor` 直接存 `app_qrzlog_logid`，天然满足第 7.4 节增量；这是四源里唯一「接口稳定 + 原生分页 + 原生增量」的源。

### 4.3 Club Log（`documented` 仅覆盖上传）

1. 上传有正式文档：`POST https://clublog.org/putlogs.php`（批量 ADIF）、`POST https://clublog.org/realtime.php`（单条），认证为注册邮箱 + **应用密码**（文档明确要求不要用账号密码）。
2. 下载本人日志 ADIF **未见官方文档**：官方知识库只文档化了「下载 OQRS 申请对应的 ADIF」（[Club Log 知识库](https://clublog.org/support/knowledgebase/developer-apis/uploads-and-adif/downloading-oqrs-adif-files/)），没有整本日志下载的接口说明。
3. 结论：**首期不做**。若后续要做，必须先由用户在其账号下验证可用性，并把结论写回本节。

### 4.4 eQSL.cc（`documented`，[DownloadInBox.txt](http://www.eqsl.cc/qslcard/DownloadInBox.txt)）

1. 接口：`https://www.eQSL.cc/qslcard/DownloadInBox.cfm?UserName=<呼号>&Password=<密码>&RcvdSince=<YYYYMMDDHHMM>`，另有 `ConfirmedOnly`/`UnconfirmedOnly`/`Archive`/`LimitDateLo`/`LimitDateHi`。
2. **两步取数**：先拿到 HTML 响应，页面里含两个 ADIF 文件链接（`.adi`/`.txt`），需再发一次请求下载文件；文件只保留几小时。
3. **语义不符（关键）**：官方原文明确「the InBox does NOT contain anything like the contents of the user's station log. These are the INCOMING cards, and not the Outgoing ones」。eQSL InBox 是**收到的 eQSL**，不是本台通联日志；`RST_SENT` 是对方发给你的 RST，`RST_RCVD` 通常为空。
4. 因此 eQSL 若接入，正确落点是「收卡/确认记录（`ReceiveRecord`）」，而不是 `QsoRecord`。这属于另一个业务面，**不进本期**，单列第 16 节待确认。
5. 附带字段：`APP_EQSL_SWL`（对方是 SWL）、`EQSL_QSLRDATE`、`EQSL_QSL_RCVD=Y`、`APP_EQSL_AG`（真实性保证）。

### 4.5 结论

首期可自动化且与「通联记录」语义一致的只有两家：**ARRL LoTW（非官方接口）** 与 **QRZ Logbook（官方接口，需订阅）**。Club Log 待验证，eQSL 语义错位。阶段 2 首选 LoTW（用户诉求点名），阶段 3 接 QRZ Logbook；其余两源按验证结果决定。

## 5. 明确不在本次范围内

1. 向外部日志**推送/上传**本系统记录（LoTW 上传需 TQSL 私钥签名与 ADIF 文件签署，属独立工程）。
2. 下载他人的日志或 QSL 确认数据（本功能只读本台呼号自己的日志）。
3. 修改或删除已存在的 `QsoRecord` 的人工字段（备注、设备、天线等）。
4. 同步后自动建卡、自动发信、自动建收卡记录等业务联动。
5. 公开页面展示外部同步状态或凭据信息。
6. 覆盖 `CardRecord`、`ReceiveRecord`、`ExchangeRequest` 任何字段。

## 7. 同步语义

### 7.1 处理流程

1. 读 `LogSyncProfile` → 校验 `enabled`。
2. 从 Secret 取凭据（缺凭据直接失败，错误码 `QSL-422-LS-0002`）。
3. 出站拉取（第 8 节），拿到 ADIF 或结构化文本。
4. 服务端解析（第 8.1 节）为字段映射结果。
5. **业务判重**（第 7.2 节）：与现有 `QsoRecord` 全量比对，决定 新增 / 更新 / 跳过。
6. 落库：内部复用既有导入作业通道（第 8.3 节），把结果同时写进 `ImportExportJob` 与 `LogSyncJob`，并写审计日志。
7. 成功后更新 `lastSyncAt` / `lastCursor`；失败写 `lastError`，按退避策略延后下次。

### 7.2 判重键（必须与前端既有规则逐字一致）

`observed`，前端权威实现位于 `ui/src/views/modules/QsoRecordModule.vue`：

- `buildQsoDuplicateKey`（`:1117-1136`）拼接顺序：`sceneType | callSign | date | time | timezone | mode | freq`，分隔符 `|`。
- 归一化 `normalizeQsoDuplicatePart`：`trim()` → `toUpperCase()` → 去空白。
- `date` 由 `parseAdifDate`（`:1239-1246`）产出 `YYYY-MM-DD`；`time` 由 `parseAdifTime`（`:1248-1255`）产出 `HHMM`；`timezone` 固定 `UTC`。
- `mode` 取 `MODE || SUBMODE`，最终写入 `QsoRecord.spec.myRigMode`（`:766`）。

后端必须实现等价类 `QsoDuplicateKey`，并在测试中与前端样例对齐（同一批 ADIF 文本在前后端算出的键必须相同）。

### 7.3 冲突处理

| 情况 | `SKIP`（默认） | `OVERWRITE` |
| --- | --- | --- |
| 键不存在 | 新增，`id` 留空由后端分配 `QSO<n>` | 同左 |
| 键存在且记录来源相同 | 跳过 | 覆盖 ADIF 可映射字段 |
| 键存在但记录来源为人工/其他源 | 跳过 | **仍跳过**（不覆盖人工数据） |

`OVERWRITE` 永远不覆盖 `remarks`（备注）与设备/天线类人工字段，只覆盖：`callSign`、`date`、`time`、`timezone`、`freq`、`myRigMode`、`rstSent`、`rstRcvd`、`operator`、`myQth`、`qth`。

### 7.4 字段映射（ADIF → `QsoRecord.spec`）

`observed`：映射规则以 `QsoRecordModule.vue:1265-1420` 为基准，后端必须复刻同一行为。

| ADIF 字段 | 目标字段 | 规则 |
| --- | --- | --- |
| `CALL` | `callSign` | 大写 |
| `QSO_DATE` | `date` | `YYYYMMDD` → `YYYY-MM-DD`，非法值整行失败 |
| `TIME_ON`（退化到 `TIME_OFF`） | `time` | `HHMM[SS]` → `HHMM`，非法值整行失败 |
| 无 | `timezone` | 固定 `UTC` |
| `FREQ` | `freq` | 原样 |
| `MODE` / `SUBMODE` | `myRigMode` | 取 `MODE`，空则取 `SUBMODE`，大写 |
| `RST_SENT` | `rstSent` | 默认 `59`；`sceneType=SWL` 时置空 |
| `RST_RCVD` | `rstRcvd` | 默认 `59` |
| `OPERATOR` / `STATION_CALLSIGN` | `operator` | 依次退化到 `StationProfile.spec.myCallSign` |
| `MY_RIG` | `myRig` | 原样 |
| `MY_ANTENNA` | `myRigAnt` | 空则取 `StationEquipment` 首个天线 |
| `MY_SIG`=`POTA` 时的 `MY_SIG_INFO`，否则 `MY_GRIDSQUARE` | `myQth` | 依前端既有优先级 |
| `QTH`（空则 `GRIDSQUARE`） | `qth` | |
| `BAND`、`TX_PWR` 等 | — | 前端把未支持字段并入 `remarks`；后端同样并入，前缀 `ADIF:` |
| `APP_QSLMS_RECORD_ID` | — | 仅用于回灌判重，不作为新增依据 |
| `APP_QRZLOG_LOGID` | — | QRZ Logbook 的增量游标，写回 `LogSyncProfile.lastCursor`，**不进 `remarks`** |
| `APP_LoTW_*`、`LOTW_*`、`EQSL_*` | — | 确认状态类字段，本期不建字段，统一并入 `remarks`（前缀 `ADIF:`），如需结构化见第 16 节待确认 2 |

## 8. 服务端组件

### 8.1 新增 ADIF 解析器（必需，`observed` 现状缺口）

`observed`：**Java 侧目前零 ADIF 处理**。对 `src/main/java` 全量 grep `ADIF|adif|CABRILLO` 无命中；ADIF 解析与导出全部在前端 `ui/src/views/modules/QsoRecordModule.vue`（3273 行）内实现，`ui/src/utils/adif-export.ts`（119 行）只负责组装。

因此本功能必须新增服务端解析器（提议 `api/QslAdifReader.java`）：

- `parse(String content)` → `List<AdifRecord>`；按 `<EOH>` 切头、`<EOR>` 切记录，字段按 `<NAME:len[:type]>` 长度语义取值（**必须按长度截取，不能按空格切**，因为地址类字段含空格）。
- 容错：缺 `<EOH>` 视为整段即记录区；字段长度与实际不符时该字段记为空并记一条告警，不整行丢弃；空记录跳过。
- 编码：ADIF 规范为 ASCII；含非 ASCII 字节时按 UTF-8 尽力解码并在 `remarks` 标注。
- 该解析器同时为「服务端导入 ADIF」铺路，但不是本期的重构目标；本期不迁移前端解析逻辑（避免顺手改坏既有导入）。

### 8.2 出站访问

- 统一用 `java.net.http.HttpClient`（`observed`：`api/QslAiService.java:8-10,54` 已用此形态），显式 `timeout`（默认 60s），**禁止自动跟随重定向**。
- 域名白名单硬编码，非白名单直接 `QSL-422-LS-0004`：`lotw.arrl.org`、`logbook.qrz.com`（首期两源）。后续接入 Club Log / eQSL 时再逐个追加，照 `QslQrzAddressLookupService.java:1499-1509` 的既有白名单写法。
- `User-Agent` 必须可识别且带插件名与版本（对齐 `QslQrzAddressLookupService.java:503-504`）。QRZ 官方明确要求可识别 UA（含呼号与脚本名、≤128 字符），否则可能被限流；LoTW 同样应带明确标识。
- 阻塞 IO 必须 `subscribeOn(Schedulers.boundedElastic())`（`observed`：`QslAiService.java:562` 既有写法）。

### 8.3 落库复用既有导入通道（关键决策）

`observed`：`api/QslImportExportJobService.java`

- `executeImportJob(ExecuteImportJobCommand command, String operator, String clientIp)`（`:104`）接受 `datasets[{dataset:"qso-record", rows:[{...}]}]`，`strategy` 支持 `SKIP`/`OVERWRITE`，并自动写 `ImportExportJob` 作业、错误行下载与审计。
- `importRows(...)`（`:816-873`）**只按资源名判重**：`resolveRowResourceName`（`:1882-1902`）里 `id` 字段非空则用它，否则生成 `QSO<max+1>`；`existingMap.get(resourceName)` 命中且 `strategy=SKIP` 才跳过。

结论与硬约束：

1. 复用 `executeImportJob` 作为落库通道，不另写一套 create/update 逻辑。
2. **业务判重必须由同步服务自己完成**，判重命中的行必须把 `id` 填成已有资源名；否则每次同步都会插入一批重复 `QSO<n>`。这是本设计最容易踩的坑。
3. 同步服务只构造 `ExecuteImportJobCommand`，不直接碰 `ReactiveExtensionClient` 写 `QsoRecord`。

### 8.4 定时调度

- 新增配置类 `@EnableScheduling` + `@Scheduled(fixedDelayString = "${...:60000}")` 轮询到期配置；单实例语义。
- 多实例部署会重复执行 → 必须按 `agents.md` 第 6 条在实现文档中标注**临时方案**，并用 `LogSyncJob` 租约（6.2）与 `lastSyncAt` 幂等兜底。
- 定时器只处理 `autoSyncEnabled=true` 且 `now - lastSyncAt >= syncIntervalMinutes` 的配置；不提供「立即补跑全部历史」的隐式行为。

## 11. 安全设计

### 11.1 凭据

1. 凭据只存 Halo `Secret`（`type=OPAQUE`），键位：`username`、`password`、`apiKey`（按源取用）。默认名：`qsl-lotw-credential`、`qsl-qrz-logbook-credential`、`qsl-clublog-credential`、`qsl-eqsl-credential`。
2. 写入形态对齐 `QslAiService.loadApiKey/upsertApiKeySecret`（`observed`：`:475-510`）与 `QslQrzAddressLookupService` 的 `CredentialSecret` 记录。
3. 任何响应、审计、错误摘要、`LogSyncJob` 字段都不得包含凭据明文；`credential-test` 只回 `{ok, message}`。
4. 导出包（现有导入导出功能）不得包含 Secret 与 `credentialSecretName` 以外的凭据痕迹——`credentialSecretName` 是资源名，允许导出。

### 11.2 日志与异常脱敏（本功能的最高风险点）

LoTW 类接口可能把凭据放在 URL 查询串里（第 4 节回填确认）。因此：

1. 禁止把含凭据的完整 URL 写进日志、异常 message、审计或 `LogSyncJob.errorSummary`。异常必须重写为固定文案，例如「LoTW 认证失败（HTTP 401）」「LoTW 请求超时（60s）」。
2. 不得使用 `exception.getMessage()` 直接透传到底层 `QslApiException`，因为底层异常可能带 URL。统一走 `safeExternalErrorMessage` 脱敏函数。
3. 若某源只能把密码放 URL，则该源必须用 `POST` 表单或 `Authorization` 头替代，不可退让。

### 11.3 出站边界

域名白名单 + 仅 HTTPS + 不跟随重定向 + 60s 超时 + 单次条数上限（默认 5000）+ 失败指数退避（1min 起，上限 24h）。禁止任何「用户自定义 URL」入口（与 QRZ 既有白名单保持一致立场）。

### 11.4 输入边界

`preview` / `run` 不接受任何由前端传入的 URL、SQL、路径或凭据；只接受 `profileName` 与 `{force}`。所有目标地址由服务端常量 + `sourceType` 决定。

### 11.5 并发

无分布式锁，采用 `LogSyncJob` 租约（6.2）+ 每配置串行。同一配置并发请求返回 `409 QSL-409-LS-0001`。

### 11.6 审计

每次 `run`（含失败）写一条 `QslAuditLog`：动作 `外部日志同步`，摘要含源、呼号、拉取/新增/跳过/失败计数，不含凭据。后端走 `QslAuditService.appendAuditLog`（`observed`：`api/QslAuditService.java:17`），由服务端系统权限写入，不依赖前端。
