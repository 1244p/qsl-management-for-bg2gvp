# QSL 卡片管理系统 使用说明书

> 适用版本：插件 2.3.47（Halo >= 2.23.0）
> 文档定位：面向站点管理员与操作员的使用手册。约束性设计文档见 `docs/spec/`，本文只讲「怎么用、出错怎么办」。
> 编写依据：仓库代码与本地实测（2026-10-31）。

---

## 1. 这是什么

一个装进 Halo 博客系统的插件，用来管理业余无线电的 QSL 卡片全流程：从通联记录、卡片版本、制卡签发、发信收信，到线上的换卡申请、线下的活动换卡、实体卡申请审核，最后做统计与审计。

四类业务各自独立成一条流水线：

| 业务 | 起点 | 终点 |
| --- | --- | --- |
| 通联业务 | 录入/导入通联日志（QSO） | 发卡、收卡、签收 |
| 线上换卡业务 | 访客在公开页提交换卡申请 | 审核 → 制卡 → 发信 → 签收 |
| 线下换卡业务 | 创建活动，现场交换 | 审核 → 制卡 → 送达确认 |
| 收卡业务 | 收到别人的卡 | 登记、关联到已有卡片或通联 |

一条通联记录可以派生出多张卡片，一张卡片对应一次收发。所有数据都留在你自己的 Halo 数据库里，插件不向外发送任何业务数据（只有你主动配置的外部日志同步会去拉取自己的通联记录）。

## 2. 安装与升级

### 2.1 安装

1. Halo 版本必须是 **2.23.0 或更高**。
2. 控制台 → 插件 → 安装 → 上传 `plugin-qsl-management-<版本>.jar`。
3. 启用插件，左侧会出现「QSL管理」菜单，默认进入总览看板。
4. 首次启动会自动创建两份默认资源：系统配置（`qsl-system-setting-default`）与本台资料（`qsl-station-profile-default`，呼号默认为示例值 `BI1KBU`）。**先去「配置 → 通信地址」改成你自己的呼号**，否则全站的呼号示例、制卡签发的地址绑定都会用示例呼号。

### 2.2 升级

- 直接上传新版本 JAR 覆盖启用即可，数据不会丢。
- 若版本跨了数据结构变更，插件的「数据 → 迁移状态」会显示当前数据结构版本与预检查结果；升级前先在那里看一眼，别跳过。
- **升级前建议导出一次数据**（数据 → 导入导出），这是唯一能原样导回业务数据的路径。

### 2.3 权限

插件把权限拆成「只读（view）」与「编辑（edit）」两档，共 18 个权限节点，覆盖 8 个菜单分组。超级管理员天然拥有全部权限；给同事开权限时，在 Halo 的「角色」里勾选对应节点即可。

- 只勾 view：能看列表与详情，不能改。
- 勾 edit：会自动带上 view 的依赖，能改。
- 普通角色看不到某个菜单，通常是**没给对应节点的 view 权限**，不是页面坏了。

## 3. 首次配置（按顺序做一遍）

| 顺序 | 菜单 | 要填什么 | 说明 |
| --- | --- | --- | --- |
| 1 | 配置 → 通信地址 | 本台呼号、姓名、地址、邮编、邮箱 | 呼号是全站示例与地址绑定的基准；公开页只披露呼号，不披露地址 |
| 2 | 配置 → 系统配置 | 访客每分钟查询次数、换卡冷却分钟数、卡片/收卡编号起点、线上换卡策略、各类邮件的发送策略 | 默认：访客 30 次/分钟、冷却 5 分钟、卡片号从 1000 起、线上换卡为「人工审核」 |
| 3 | 配置 → 本台设备 | 电台、天线、功率 | 制卡与通联记录里可选用 |
| 4 | 配置 → 本台卡片 | 卡片版本（名称、图案、是否启用） | 一个版本就是一套卡面；内置「不发卡」版本用于只收不发的情形 |
| 5 | 数据 → 卡片局管理 | 常用卡片局（名称、地址） | 实体卡申请只能从这里选，不能手填 |
| 6 | 数据 → 地址管理 | 常用通信地址簿 | 制卡时可复用，避免手打错 |
| 7 | 数据 → 设备库维护 | 对方电台/天线字典 | 用于统一写法，便于统计 |

## 4. 通联业务

菜单：**通联业务**

| 页面 | 做什么 |
| --- | --- |
| 通联日志 | 录入/导入通联记录（QSO），支持 ADIF 3.1.7 与 Cabrillo 3.0 |
| 创建卡片 | 从通联记录生成待发卡片（卡片记录） |
| 实体卡申请审核 | 审核访客在公开页提交的实体卡申请 |
| 制卡签发 | 打包、填地址、签发卡片，生成卡片编号 |
| 发信确认 | 登记已寄出、选择发送方式 |
| 送达确认 | 登记对方已收到、签收日期 |

### 4.1 导入通联记录

1. 进「通联日志」→ 导入，选 ADIF（`.adi`/`.adx`）或 Cabrillo（`.log`/`.cbr`）。
2. 导入按「场景 + 呼号 + 日期 + 时间 + 时区 + 模式 + 频率」判重，重复记录会被跳过，不会重复插入。
3. ADI 文件只允许可打印 ASCII：整条记录里有非 ASCII 字符时该条不会导出，改用 ADX 或 INTL 字段。
4. USB/LSB 会归一成「模式 SSB + 子模式 USB/LSB」。

### 4.2 批量编辑

通联日志与卡片记录的批量编辑是统一模板：勾选行 → 选要改的字段名 → 按字段类型显示候选项或输入框 → 确认修改。

### 4.3 制卡签发的地址规则（最容易踩的坑）

- 打包时**不能用页面上临时填的候选地址覆盖卡片上已有的地址与邮箱**。
- 只有你点了「确认绑定地址」，地址才会写进卡片。
- 只有呼号精确匹配、且处于「未打包 / 未发出 / 未签收」的卡片允许改地址。
- 已发出的卡片改地址没有意义，改了会导致账面与实际不符。

## 5. 线上换卡业务

菜单：**线上换卡业务**

1. 访客在公开页 `/online_eyeball` 提交申请（填写呼号、地址、希望的卡片）。
2. 「换卡申请审核」里逐条处理：通过 / 拒绝。拒绝要写理由，会通过邮件告知。
3. 通过后可「创建卡片」，再进「制卡签发」打包签发。
4. 「发信确认」→ 访客收到后由访客在公开页 `/rp` 自行签收，或你在「签收确认」里代为登记。
5. 「导入数据」可用于批量导入历史换卡记录（BH6SYX 格式）。

**冷却与限流**：同一访客重复提交受冷却时间限制（默认 5 分钟，配置里填 0 即关闭）；访客查询受「每分钟次数」限制（默认 30 次）。超限返回 `QSL-429-0001`。

---

## 6. 线下换卡业务

菜单：**线下换卡业务**

1. 「创建活动」建立一次线下活动（名称、日期、地点）。
2. 现场交换后「创建卡片」登记对方呼号与卡片版本。
3. 「制卡签发」批量签发，「送达确认」登记结果。
4. 内置活动「日常线下换卡」不占活动记录，用于零散换卡。

---

## 7. 收卡业务

菜单：**收卡业务**（三页：通联收卡 / 线上换卡收卡 / 线下换卡收卡）

- 收到卡片后登记：呼号、卡片编号、收卡日期、关联的卡片记录。
- 收卡记录编号有独立起点（默认 0），与卡片编号是两套序列。
- 收卡记录可以关联到系统里已有的卡片；关联不上的（对方没走系统）也可以只登记。
- 公开页 `/rp` 允许访客自助签收，签收结果会写进对应卡片。

---

## 8. 审计与查询

菜单：**审计**（通联记录查询 / 卡片记录查询 / 收卡记录查询 / 统计报表 / 审计日志）、**数据**（卡片异动）

- 三个查询页支持按呼号、日期范围、场景筛选，结果可导出。
- 「统计报表」按场景、月份、呼号维度汇总卡片数与收发数量。
- 「卡片异动」记录重发、发卡异常、标记重发等动作，可对单条卡片执行「重发 / 标记异常 / 标记重发」。
- 「审计日志」记录谁在什么时候改了什么。**它会持续增长**，建议定期按时间清理。

## 9. 外部日志同步（从 LoTW / QRZ 自动拉通联记录）

菜单：**数据 → 外部日志同步**

### 9.1 支持的数据源

| 数据源 | 需要什么 | 说明 |
| --- | --- | --- |
| ARRL LoTW | LoTW 用户名 + 密码 | LoTW 没有官方 API，插件用的是官方报表下载地址（ADIF）。用户名多数等于主呼号，但**不一定**；密码是登录 lotw.arrl.org 的密码，与 ADIF 签名密码可能不同 |
| QRZ Logbook | 一长串 API Key（8 位 Key 或 `AJ...` 组合 Key），密码留空 | 官方 FETCH 接口，**读取需要订阅** |

> 命名上刻意不叫「LoTW 同步」：ARRL 的商标条款限制第三方产品使用 LoTW 名称。

### 9.2 建配置的步骤

1. 「新建或选择配置」→ 填配置名（如 `log-sync-lotw-bg2gvp`）。
2. 选数据源、填本台呼号、填默认场景（一般 QSO）、填冲突策略。
3. 「账号凭据」区填账号与密码（QRZ 只填 Key，密码留空），点「保存凭据」。
   - 密码**只进 Halo 的 Secret 存储**，不会写进配置、不进导出包、不回显、不进日志。
   - 保存后页面显示「账号已保存 / 密码已保存」，再点「测试连接」验证。
4. 「保存配置」→「立即同步」。

### 9.3 同步语义

- **判重键**：场景 + 呼号 + 日期 + 时间 + 时区 + 模式 + 频率，与前端手工导入完全一致，两边不会互相打架。
- **冲突策略**：`保留已有，跳过重复`（默认，不动已有记录）/ `覆盖已有`（只覆盖呼号、日期、时间、时区、模式、RST、操作员、本台/对方网格与地址，**永不覆盖备注与手工填的设备天线字段**）。
- **游标**：LoTW 用报表头部 `APP_LOTW_LASTQSORX`，QRZ 用 `app_qrzlog_logid`（官方分页语义是「大于等于」，所以游标取最大值 +1）。游标可以随时「重置游标」，重置后下次从最早记录重新拉（判重会兜住重复）。
- **定时同步**：打开「启用自动同步」并按「同步间隔（分钟）」跑（最低 60 分钟）。插件每分钟检查一次是否到期；上一次没跑完时跳过本轮；失败也遵守间隔，不会连打上游。

### 9.4 失败排查对照表

| 页面提示 | 原因 | 怎么办 |
| --- | --- | --- |
| 账号或密码未配置（`QSL-422-LS-0002`） | 只存了账号没存密码 | 在凭据区把密码填上并保存 |
| LoTW 返回的是登录页面… | 用户名/密码不对，或账号未启用 LoTW | 核对用户名（不是主呼号也常见）；页面上会带出 LoTW 自己的措辞 |
| 状态码 503 / `Page Request Limit`（`QSL-429-LS-0001`） | LoTW 限流：同一账号每分钟只允许一次下载 | 等一分钟再点；插件会自动等 65 秒重试一次 |
| 同一账号距上次请求仅 N 秒（`QSL-429-LS-0002`） | 触发了插件自己的账号级间隔闸（LoTW 60 秒） | 等提示里写的秒数 |
| 该配置已有一次同步在进行（`QSL-409-LS-0001`） | 上一次作业还在跑 | 等它结束，或点「强制停止」 |
| 该配置没有正在进行的同步作业（`QSL-409-LS-0002`） | 点了强制停止但没有运行中的作业 | 正常，直接重新同步 |
| 该配置已停用，不能同步（`QSL-400-LS-0004`） | 配置里「启用配置」没勾 | 勾上再同步 |
| QRZ 报 `RESULT=AUTH` | Key 无效或未订阅 FETCH | 核对 Key；确认账号已订阅日志读取 |

作业表可以点行展开看失败明细；作业不会永久停在「进行中」——超过时限或插件重启时会被标记为「作业执行被中断」。

## 10. 对外公开的页面

访客不需要登录，只披露呼号，不披露地址与邮箱。

| 用途 | 地址 | 短地址 |
| --- | --- | --- |
| 公开查询某呼号的卡片 | `/apis/api.qsl-management.bi1kbu.com/v1alpha1/cards/page?callSign=BG2GVP` | — |
| 线上换卡申请 | `/online_eyeball` | `/oe` |
| 线下换卡确认 | `/eyeball` | `/eb` |
| 访客自助签收 | `/receipt_public` | `/rp` |
| 实体卡申请 | `/qsl_card` | — |

在文章里插入卡片的方式（短代码）：

```
[qsl-card callSign="BG2GVP"]
[qsl-receipt-card callSign="BG2GVP" cardId="C0001"]
[qsl-online-exchange-card]
[qsl-offline-exchange-card]
```

`callSign` 必须是 3~16 位的字母、数字或 `-`。所有访客接口都按「接口 + 客户端 IP」限流，超限 `QSL-429-0001`。

## 11. 数据导入导出

菜单：**数据 → 导入导出**

- **导出格式**：ADIF 3.1.7（ADI / ADX）、Cabrillo 3.0（比赛日志）、CSV 数据集（按数据集逐表导出）。
- **导入**：先跑「预检查」看会新增/更新多少条，再执行；作业里能看到逐行错误。
- **备份建议**：每次大改动前先导出一个 CSV 数据集包（ZIP），这是唯一能原样导回业务数据的路径。
- 作业历史也会一直留着，可在该页清理。

## 12. 制卡打印工具（可选）

仓库里的 `tools/CardPrint` 是一个独立的 Python 桌面工具，用来自动排版与打印卡片。

- 需要 Python 3.10+，依赖 PySide6 与 qrcode。
- 通过「桥接服务」连到你的 Halo 站点（默认 `http://localhost:8090`），从插件读取待打印卡片、回写打印状态。
- 二维码支持短路径 `/eyeball`、`/online_eyeball`、`/rp`。
- ⚠️ 二维码里硬编码的是旧版大写短路径。插件计划在 3.0.0 移除旧路由，**届时这些二维码会失效**；在此之前请确认你的二维码已改用小写短路径。

## 13. 常见问题

**Q：菜单里少了「制卡签发」？**
该角色没有「制卡签发」的权限节点。让管理员在角色里勾上 `card-issue` 的查看权限（编辑权限会自动带上查看依赖）。

**Q：点按钮提示 403 但页面没崩？**
权限不足。插件在服务端按「菜单节点 + 接口资源」双重校验，403 时请求不会进业务逻辑，也不会写坏数据。

**Q：访客说打不开公开页？**
先看公开页是否被 Halo 的「页面/文章」占用同名路径；再确认插件已启用。公开页走匿名角色，若在 Halo 里误删了 `qsl-management-public-view/submit` 两个聚合角色，公开页会 403。

**Q：卡片编号跳号了？**
编号靠扫描现有最大号 +1 生成，删除过卡片就会跳号。这是正常现象。

**Q：数据存在哪，怎么清空？**
全部在 Halo 数据库（20 种自定义扩展 + Secret）、附件库（卡片图片）与浏览器 localStorage（导出参数）。详见 `docs/reports/插件数据清理方案-2026-10-31.md`。

## 14. 版本与升级注意事项

- 正式打包前版本号同时改两处：`src/main/resources/plugin.yaml` 与 `gradle.properties`。
- 升级不丢数据；**卸载插件也不会自动删数据**，重装后旧数据仍在。
- 跨版本数据结构变更以「数据 → 迁移状态」为准，别只看页面提示。
- 2.4.0 起推荐用根路径（`/oe`、`/eb`、`/rp`）访问公开页；旧的大写路由仍在，计划 3.0.0 移除。
